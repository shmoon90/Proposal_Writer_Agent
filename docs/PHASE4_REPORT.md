## 3. 실행 조건과 게이트

- 산출물 생성·QA는 **Gate 1(요구사항 추출·독립 검증) PASS**가 코드로 확인될 때만 시작된다(`StepRunner.run_generation/run_qa` → `GateService.require`). 테스트 `test_generation_blocked_until_gate1`.
- 기술적으로 중요한 미확인 사항(구현 가능성 unknown/infeasible, 조사 미확인 항목, 수용여부 검토 필요, 기본값 WBS, 기술 미정 구성 요소, 문안의 미확인 주장)은 `review_items`로 모아 QA 보고서·UI·Gate 4 사유에 표시한다.
- Gate 4: QA 오류 → FAIL(승인 불가), 그 외 → NEEDS_HUMAN_REVIEW(의견 기록 후 승인) → 최종본 확정.

## 4. 계획 엔진 (결정적)

- 기간: UI 입력 → RFP `schedule_hints`의 "N개월" → 없으면 입력 요청(`ValidationError`).
- WBS: 에이전트(`planner`) 초안이 있으면 사용, 없으면 요구사항에서 3단계 기본 WBS 생성(공수 기본값은 "검토 필요" 표기). 산정 근거 없는 항목 거부.
- 검증: 미존재 참조·자기 참조·순환·3단계 초과·기간 0·명시 날짜 충돌·전체 기간 초과(경고).
- 일정: 영업일(주말·설정 공휴일 제외) 기준 FS/SS/FF/SF + lag 전진 계산, 상위 항목 롤업.
- 인력: 작업별 역할 비율로 공수 분배 → 월별 M/D → 역할별 M/M·인원(월 최대 올림). 1 MM = 20 M/D 가정 명시. 단가는 입력란, 없으면 비용 미계산.
- 업무 유형(선행/후행/단독)은 표시용이며 의존 관계는 별도 시트로 관리.

## 5. 목차·시각 자료 규칙

- 목차 우선순위: 에이전트 문안 → RFP의 "제안서 목차/구성/작성 지침" 항목(블록에서 추출) → 평가 기준·과제 목적·데이터 유무로 선택한 기본 목차(보안·운영·평가 섹션은 해당 데이터가 있을 때만).
- 모든 시각 자료는 코드가 데이터로 그린다. 수치가 없는 차트는 만들지 않는다(공수 차트는 배정이 없으면 생성 안 함). 외부 이미지는 사용하지 않는다.
- 제출용·발표용은 같은 `GenerationContext` 수치만 쓰며, QA가 기간·총 MM·투입 인원 문자열과 구성 요소 기술명을 양쪽 PPT 텍스트에서 대조한다.

PPT 열림·가로 16:9·도형 경계·텍스트 겹침·넘침 추정, Excel 열림·필수 시트/컬럼·수식 형식·날짜 순서·요구사항 ID 집합 일치·WBS 상위 참조·산정 근거·'성공' 오표시, WBS↔인력 공수 일치, 배정 합계 일치, PPT 간 핵심 수치 일치, 기술명 언급, 필수 요구사항의 제출용 PPT 추적성, 발표용 '미정/검토 필요' 과다.

## 7. 미해결 이슈·사람 검토 필요 (스모크 기준)

- 발표용 PPT '미정' 13회 경고: 기술 스택이 기본값이라 발생. 아키텍처 에이전트 실행(크레딧 필요) 또는 수동 입력 후 재생성 필요.
- 수용 여부가 모두 '검토 필요': 사용자가 요구사항 화면에서 수용/조건부/미수용을 정해야 한다.
- WBS 공수 기본값: 실제 생산성으로 검증되지 않았다. planner 에이전트 또는 사용자 입력으로 대체해야 한다.
- 에이전트(architect/planner/proposal_writer) 결과를 쓰는 경로는 Fake 러너로만 검증했고 실제 LLM 출력으로는 검증하지 못했다(크레딧, R-21).
- PPT 텍스트 넘침 검사는 글자 수 기반 추정이다. 실제 렌더링 확인은 PowerPoint에서 열어 봐야 한다.
- 화면·테스트 ID는 설계 단계 데이터가 없어 전부 `미정`이다.
