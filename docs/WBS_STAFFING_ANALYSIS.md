# WBS·인력 투입계획 샘플 분석 (구조 전용, Phase 15)

고객이 제공한 개발 일정 계획(상세 WBS) 1건, 보고용 일정 계획(약식 WBS) 1건, 월별 투입계획 1건을 분석한 결과다. **샘플은 실제 과제 자료라 저장소 밖에만 두고 참고만 한다.** 고객사·사업명·담당자 이름·업무 항목 원문은 적지 않고 시트 구성·컬럼·색·수식·분량만 남긴다. 결과는 `generators/excel/wbs_gantt.py`·`staffing_plan.py`(양식), `planning/service.py`(마일스톤·수행 조직), `ingest/excel_reader.py`·`changes/baseline_service.py`(재적재), `agents/prompts/planner.md`(에이전트)에 반영했다.

## 1. 구조

| 요소 | 상세 WBS (개발용) | 약식 WBS (보고용) | 월별 투입계획 |
|---|---|---|---|
| 시트 | 1장 (B2부터 시작, 1열·1행 여백) | 1장 | 1장 |
| 머리글 | 2행: `구분 · 항목(2열 병합: 항목·세부) · 수량 · 담당` + **월 번호**(4주 병합) / 2행째 **주차 1~4** | 2행: `구분 · 항목(2열) · 시작일 · 종료일` + 월(주 수만큼 병합) / 주차 | 제목 행(`* <사업명> 월별 투입계획`) + 1행: `구분 · 등급 · 월(6~11) · 계 · 비고` |
| 행 수 | 46 (구분 4 × 항목 22 × 세부) | 89 (구분 6 × 단계 27 × 세부 61) | 9 (역할·등급별 8 + 계) |
| 병합 | 구분 세로(B4:B14 …), 항목 세로(C6:C7 …) | 구분·단계 세로, 사업관리 행은 B4:D4 가로 | 하단 `계` 행 B:C |
| 날짜 | **없음** (주 단위 채움만) | 시작일·종료일 datetime, `m/d` 표시 | 월 번호만 |
| 간트 표현 | 주 열 셀 채움(테마 파랑 2종, 한 줄 메모 텍스트 포함) | 주 열 셀 채움(파랑), 사업관리 행에 `착수·착수보고·중간보고·완료보고·오픈·종료` 라벨(주황), 일부 열 다른 색(오픈) | — |
| 수식 | 없음 | 없음 | `계 = SUM(월…)`, 하단 계 행도 SUM |
| 담당/인원 | 담당자 이름 1칸(대부분 빈값) | 없음 | 역할(PM·기획·디자인·퍼블·개발)별 등급, MM 0.25 단위 |
| 비고 | 주 셀 안에 진행 메모("시안 전달 필요" 등) | — | 변경 이력 메모(`* 2MM -> 2.75MM`) |
| 틀 고정 | G4 (담당 뒤) | E4 (종료일 뒤) | 없음 |
| 글꼴·크기 | 11pt, 머리글 회색(theme 0 -5%) | 11pt 굵게 머리글 | 11pt, 머리글 테마색 80% |

## 2. 관찰 → 적용

| 관찰 | 적용 |
|---|---|
| 상세와 보고용이 같은 항목 계층을 공유하되 보고용은 컬럼을 줄이고 마일스톤 행을 둔다 | 한 파일에 **WBS(상세)** + **약식WBS(보고용)** 시트. 보고용은 구분·단계·항목·시작일·종료일 + 같은 주 단위 간트, 첫 행 `사업관리 / 마일스톤`에 라벨 |
| 간트가 별도 시트가 아니라 표 오른쪽에 붙은 월/주차 2단 머리글 | 두 시트 모두 컬럼 오른쪽에 **1행 월(YYYY-MM 병합)·2행 월 내 주차** 격자. 채움색: 단계 진한 파랑, 활동 파랑, 작업 연파랑, 진척(진척율·완료) 녹색, 마일스톤 주황 ◆. QA(QA-FILE-08)는 머리글에서 주 시작(월요일)을 복원해 기준 일정과 대조 |
| 사용자 요구 컬럼: 개발 조직·개발 항목·개발자·계획/실제 시작·종료일·진척율·간트 | `WBSItem`에 `category(구분)`·`organization(개발 조직)`·`assignee(개발자)`·`quantity(수량)`·`progress_pct(진척율)`·`milestone` 추가. 상세 시트 25열: 식별 → 개발 항목 → 담당 → 일정(계획·실제·기간·진척율·상태) → 공수 → 관계 → 비고 |
| 마일스톤(착수·보고·오픈·종료)은 사업관리 행 | planner 초안 `milestones[{name, timing}]`(start/mid/end/after:<code>/±Nw) → 코드 `0`(사업관리) 아래 공수 0·1일 항목. 에이전트가 주지 않으면 기본 5개(검토 필요) |
| 투입계획은 역할(구분)·등급별 행 + 월별 MM + 계 수식 + 하단 합계 행 + 변경 메모 | **투입계획** 시트를 **구성원별** 행(조직·역할·구성원·등급·담당·투입 시작/종료월·월별 MM·계(SUM)·비고)으로 바꾸고 하단 합계 행(월별 SUM·총계). 구성원 이름이 없으면 `역할N` 자리표시. 역할 단위(인원·단가·비용 수식)는 **역할요약** 시트 |
| 수행 조직 구성(역할·등급·인원)은 사람이 정하는 값 | planner 초안 `team[{organization, role, grade, name, headcount, skills, duties}]` → `StaffRole`(조직·등급·인원·구성원). 월별 부하로 계산한 필요 인원보다 적으면 검토 메모 |
| 고객 상세 WBS는 WBS ID·날짜가 없고 병합 셀 계층(구분>항목>세부)만 있다 | 재적재 시 WBS ID가 없으면 병합 셀을 아래로 채우고 **구분(1) > 단계(1.1) > 항목(1.1.1)** 코드를 발급(경고). 주 단위 채움(날짜 없음)은 읽지 않는다. 동의어: 구분·항목·개발 항목·수량·담당(개발자)·진척율·개발 조직 등 |
| 월별 투입계획의 역할 행 반복·등급·계 | 재적재 시 같은 역할 행을 묶어 인원·구성원(이름 열이 있을 때)·등급·기준 MM을 남긴다. `구분`은 역할 동의어 |

## 3. 넣지 않은 것

- 주 셀 안의 진행 메모(텍스트)는 생성하지 않는다. 사람이 간트 셀에 직접 적을 수 있다(편집 가능).
- 날짜 없는 주 단위 채움으로 일정을 역산하지 않는다(해당 월·주차가 어느 연도인지 문서에 없음).
- 보고용의 '오픈' 전용 색, 투입계획의 변경 메모 자동 생성은 없다(비고 열은 사람이 쓴다).
