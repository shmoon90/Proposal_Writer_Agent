## 1. 검증되지 않은 것 (지원한다고 주장하지 않음)

| 항목 | 상태 | 비고 |
|---|---|---|
| **실제 Claude 모델 호출** | 미검증 | Anthropic 계정 크레딧 부족(`Credit balance is too low`)으로 모든 에이전트 역할(추출·검증·분석·조사·설계·계획·문안·QA·의미 비교)의 실제 응답 품질·비용을 확인하지 못했다. SDK 프로세스 기동·MCP 연결(비용 0)과 모의 응답 경로만 검증. 크레딧 확보 후 `scripts\run_phase2_llm.py`, `pytest -m llm`부터 실행 필요 |
| 내장 WebSearch/WebFetch 실제 검색 | 미검증 | 도구 노출만 확인 |
| Windows 11·Python 3.12.10 외 환경 | 미검증 | macOS·Linux·Python 3.13 등은 시도하지 않았다. `pyproject.toml`이 3.12만 허용 |
| 다중 사용자·동시 접속·네트워크 공개 | 미지원 | 로그인·권한 없음. 단일 PC 로컬 사용 전제 |
| 대형 RFP(수백 페이지) 성능 | 미측정 | 모의 RFP(수 페이지) 기준으로만 검증 |
| OCR 정확도(실제 스캔본) | 부분 | 모의 한국어 이미지 신뢰도 0.94~0.97. 실제 저품질 스캔은 미확인 |

## 2. 미구현 기능과 이유

| 기능 | 이유·대안 |
|---|---|
| HWP/HWPX/DOC 추출 | 순수 Python 변환기가 없고 외부 변환기 설치는 정책 미확정(D-08). 등록은 되고 추출 시 "변환 후 재업로드" 안내 |
| 제안 프로젝트 → 구축 프로젝트 데이터 승계(6.7) | 범위에서 제외. 제안 단계가 만든 Excel을 구축 프로젝트에 업로드하면 같은 적재 경로로 사용 가능 |
| 프로젝트 삭제·아카이브 UI | 산출물·이력 보존 원칙. 수동 정리 절차만 제공([ADMIN_GUIDE.md 9절](ADMIN_GUIDE.md)) |
| DB 자동 복원(스냅샷 → DB) | 스냅샷 JSON은 저장하지만 되돌리는 기능은 없다 |
| 사용자 PPT 템플릿 적용(D-06) | 기본 레이아웃만 생성. 템플릿 반영은 미구현 |
| 외부 전송 고지·마스킹 정책(D-10) | 정책 미확정. 프롬프트에 RFP 블록이 포함되어 전송된다는 점만 문서화 |
| 00_Project_Summary 폴더 내용 | 예약만 되어 있고 파일을 생성하지 않는다 |

## 3. 부분 구현·휴리스틱 (사람 확인이 전제)

| 항목 | 한계 |
|---|---|
| 의미 기반 비교(구축) | 규칙 기반(문자 bigram 유사도 + 의도 키워드). 복합 문장·영문 혼용·긴 서술에서 ADD/MODIFY 경계가 보수적이며, 모호하면 사용자 확인으로 넘긴다. AI 덧붙임은 미검증 |
| 변경 공수·일정 영향 | 수정 공수는 유사도 비율(0.2~0.6) 추정, 신규 Task는 유사 Task 중앙값. '범위'와 근거를 표시하고 사용자 확정값으로 대체 가능 |
| RFP 적합성 QA | 의무 표현 키워드·정규화 문자열 기반. 누락·과잉은 NEEDS_HUMAN_REVIEW로만 낸다(FAIL은 출처 불일치·범위 오표기 등 확정 가능한 경우) |
| 기술 타당성 QA | 기술 조사 기록이 있어야 의미가 있다. 조사 미실행 시 Gate 2는 항상 NEEDS_HUMAN_REVIEW |
| 자동 수정 | '기준 데이터로 산출물 재생성'만 허용. 데이터 기인 실패(요구사항↔WBS 누락, 공수 불일치)는 수정 제안만 |
| PPT 텍스트 넘침·겹침 검사 | 글자 수·좌표 기반 추정. 최종 승인 전 PowerPoint에서 육안 확인 필요 |
| 기본값 산출물 | 아키텍처·계획 에이전트를 실행하지 않으면 코드 기본 구성(기술 '미정', 공수 기본값)이 들어가고 "검토 필요"로 표시된다 |
| 승인자 식별 | 이름 문자열 기록만. 인증 없음(D-09) |
| 변경 요청 문서 업로드 | 줄 단위로 항목을 나누므로 제목·머리글 줄이 후보로 올라올 수 있다(거절로 처리) |
| 간트 차트 | Excel 셀 채움(주 단위)과 PNG. 간트 전용 도구 호환 형식(MS Project 등)은 없다 |
| 제안서 템플릿 인식 (Phase 12) | `generators/pptx/template.py`는 업로드 PPTX에서 반복 좌표의 상단 텍스트 상자(머리글), 머리글 아래 넓은 도형(리드), 큰 글꼴·로마숫자 슬라이드(장 표지), 글꼴·표 머리글 색을 휴리스틱으로 읽는다. 실샘플 2종(A4 세로, Ⅰ장·Ⅲ장)과 가상 픽스처로만 확인했다. 머리글이 자리표시자(placeholder)로만 구성된 템플릿, 슬라이드마다 좌표가 다른 템플릿은 머리글을 못 찾아 기본 배치로 내려간다(경고). 장 전용 레이아웃이 없는 장은 레이아웃의 장 이름·로마숫자를 덮어쓰는 방식이라 띠 색이 그라데이션이면 어색할 수 있다. A3 별지처럼 다른 용지 크기는 한 파일에 섞지 못한다. 템플릿의 그림·도식(아이콘·흐름도)은 재현하지 않으며 글머리·표·구성도 이미지로 채운다 |
| RFP 구조 인식 (Phase 11) | `ingest/rfp_profile.py`는 절 제목 키워드(요구사항·평가·제출·작성요령 등), `[A-Z]{2,5}-\d{2,4}` 형태의 RFP 자체 ID, '요구/사항/세부' 같은 세로 병합 라벨, 로마숫자·숫자 목차 행, '항목 \| 배점' 표를 정규식·휴리스틱으로 인식한다. 공공 SI 표준 양식(고객 제공 샘플 1건, 48쪽)과 가상 DOCX 픽스처로만 확인했다. 제목 번호가 없거나 ID 체계가 다른(예: 'R-1', '기능-01') 문서는 절·ID를 잡지 못하고 경고 후 문장 단위 추출로 내려간다. 커버리지 검사(QA-RFP-07)는 ID↔요구사항 연결 유무만 보며 내용의 충분성은 판단하지 않는다 |

## 4. 환경 제약 (이 개발 PC에서 확인)

- Windows 앱 제어 정책이 PyMuPDF(`_mupdf.pyd`)와 matplotlib(`_backend_agg`) DLL을 차단해 pdfplumber+pypdf+pypdfium2, Pillow 직접 드로잉으로 대체했다. 다른 PC에서는 문제가 없을 수 있으나 의존성은 현재 구성을 유지한다.
- OCR 모델은 첫 실행 시 인터넷에서 내려받는다. 오프라인 PC는 스캔 PDF를 처리하지 못한다.

## 5. 알려진 사소한 동작

- 제안 단계에서 파일을 삭제한 뒤 재생성하면 폴더 기준으로 버전명이 다시 `v1.0`부터 매겨진다(DB 레코드는 별도로 누적).
- 변경 반영 재시도 시 파일은 새 타임스탬프로 다시 생성되고 이전 생성 파일은 남는다(덮어쓰기 없음).
- 구축 단계 프로젝트에 과제 종료일을 입력하지 않으면 일정 초과 여부를 판단하지 않고 안내만 한다.
