## 2. 미구현 기능과 이유

| 00_Project_Summary 폴더 내용 | 예약만 되어 있고 파일을 생성하지 않는다 |

| 항목 | 한계 |

| 의미 기반 비교(구축) | 규칙 기반(문자 bigram 유사도 + 의도 키워드 + Phase 14 문맥 관점 비교: 주체·행위·수치·화면·품질·연계·데이터·입출력·규칙 단어 집합 차이). 동의어·문장 구조 변화는 잡지 못하며 복합 문장·영문 혼용·긴 서술에서 ADD/MODIFY 경계가 보수적이고, 모호하면 사용자 확인으로 넘긴다. AI 덧붙임(관점·난이도·공수 힌트)은 미검증 |

| 제안서 템플릿 인식 (Phase 12) | `generators/pptx/template.py`는 업로드 PPTX에서 반복 좌표의 상단 텍스트 상자(머리글), 머리글 아래 넓은 도형(리드), 큰 글꼴·로마숫자 슬라이드(장 표지), 글꼴·표 머리글 색을 휴리스틱으로 읽는다. 실샘플 2종(A4 세로, Ⅰ장·Ⅲ장)과 가상 픽스처로만 확인했다. 머리글이 자리표시자(placeholder)로만 구성된 템플릿, 슬라이드마다 좌표가 다른 템플릿은 머리글을 못 찾아 기본 배치로 내려간다(경고). 장 전용 레이아웃이 없는 장은 레이아웃의 장 이름·로마숫자를 덮어쓰는 방식이라 띠 색이 그라데이션이면 어색할 수 있다. A3 별지처럼 다른 용지 크기는 한 파일에 섞지 못한다. 템플릿의 그림·도식(아이콘·흐름도)은 재현하지 않으며 글머리·표·구성도 이미지로 채운다 |
| RFP 구조 인식 (Phase 11) | `ingest/rfp_profile.py`는 절 제목 키워드(요구사항·평가·제출·작성요령 등), `[A-Z]{2,5}-\d{2,4}` 형태의 RFP 자체 ID, '요구/사항/세부' 같은 세로 병합 라벨, 로마숫자·숫자 목차 행, '항목 \| 배점' 표를 정규식·휴리스틱으로 인식한다. 공공 SI 표준 양식(고객 제공 샘플 1건, 48쪽)과 가상 DOCX 픽스처로만 확인했다. 제목 번호가 없거나 ID 체계가 다른(예: 'R-1', '기능-01') 문서는 절·ID를 잡지 못하고 경고 후 문장 단위 추출로 내려간다. 커버리지 검사(QA-RFP-07)는 ID↔요구사항 연결 유무만 보며 내용의 충분성은 판단하지 않는다 |

## 4. 환경 제약 (이 개발 PC에서 확인)

- Windows 앱 제어 정책이 PyMuPDF(`_mupdf.pyd`)와 matplotlib(`_backend_agg`) DLL을 차단해 pdfplumber+pypdf+pypdfium2, Pillow 직접 드로잉으로 대체했다. 다른 PC에서는 문제가 없을 수 있으나 의존성은 현재 구성을 유지한다.
- OCR 모델은 첫 실행 시 인터넷에서 내려받는다. 오프라인 PC는 스캔 PDF를 처리하지 못한다.

## 5. 알려진 사소한 동작

- 제안 단계에서 파일을 삭제한 뒤 재생성하면 폴더 기준으로 버전명이 다시 `v1.0`부터 매겨진다(DB 레코드는 별도로 누적).
- 변경 반영 재시도 시 파일은 새 타임스탬프로 다시 생성되고 이전 생성 파일은 남는다(덮어쓰기 없음).
- 구축 단계 프로젝트에 과제 종료일을 입력하지 않으면 일정 초과 여부를 판단하지 않고 안내만 한다.
