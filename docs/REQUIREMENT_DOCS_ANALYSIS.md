# 요구사항 정의서·추적표 샘플 분석 (구조 전용, Phase 14)

고객이 제공한 요구사항 정의서 2건(서로 다른 과제)과 요구사항 추적표 1건을 분석한 결과다. **샘플은 실제 과제 자료라 저장소 밖에만 두고 참고만 한다.** 이 문서에는 고객사·사업명·담당자·제품명·원문 문장을 적지 않으며 시트 구성·컬럼·색·서식·분량 같은 **구조와 통계만** 남긴다. 분석 결과는 `generators/excel/requirement_spec.py`·`trace_matrix.py`(양식), `ingest/excel_reader.py`(동의어·재적재), `requirements/approach.py`(구현방안 자동 작성), `changes/semantic.py`·`impact.py`(문맥 비교·난이도 가중)에 반영했다.

## 2. 컬럼 구성

### 2.1 정의서 샘플 A (11열)

업무구분 · 요구사항 ID · 요구사항 명 · 요구사항 상세내역 · 출처 · 고유번호(RFP 번호) · 요구사항 변경여부 · 검토 및 협의 내용 · 분류 · 수용여부 · 비고

- ID는 `REQ-<RFP번호>-NN` 형식으로 **RFP의 한 번호 아래 세부 항목을 여러 행**으로 둔다(요구사항 명은 상위 과제명, 상세내역이 `N) 제목 + - 세부` 구조).
- "검토 및 협의 내용"은 `@검토 의견` / `@ 협의 사항 (날짜)` 머리 + `*`·숫자 글머리로 고객 협의 기록을 남기고, 비고에 회의록 참조를 적는다. 평균 173자·7.6줄.
- **구현방안 컬럼이 없다** (사용자 지적 사항 → 본 시스템은 요구사항마다 구현방안을 자동 작성).

### 2.3 추적표 샘플 C — 검사기준서(기능) (23열, 묶음별 색)

| 묶음 (색) | 컬럼 |
|---|---|
| 요구사항 (연파랑 DBEEF3) | No · Level1(대) · Level2(중) · 요구사항 ID · 요구사항명 · 세부 요구사항 · 유형 |
| 수용 (연주황 FDEADB) | 수용여부(수용/제외/일부제외 + 제외 사유) · 생성/변경일자 |
| 설계 (황갈 DDD9C3) | 화면/보고서ID · 화면/보고서명 · 배치ID · 배치명 · 인터페이스ID · 인터페이스명 · 프로그램ID · 프로그램명 · 담당자(참고용) |
| 구현 (진황갈 C4BD97) | 단위테스트케이스ID |
| 테스트 (보라 CCC1DA) | 통합테스트케이스ID · 통합테스트케이스명 |

- 해당 없음은 `N/A`, 여러 ID는 셀 안 줄바꿈으로 나열. 한 요구사항 ID가 세부 요구사항별로 여러 행(150 ID → 252행).
- 검사기준서(비기능)(10열): No · Level1 · Level2 · 요구사항 ID · 요구사항명 · 요구사항 내용 · **구현내용** · 검사기준 · 수행결과 · 비고. 구현내용 평균 137자·2.8줄(글머리 `ㅇ`·`-`), 검사기준 평균 14자.
- 숨김 옛 추적표(13열): 분석 요구사항ID · 분석 요구사항명 · 오픈(1차/2차) · 유형 · 단위기능 ID · 프로세스명 · 화면 ID · 화면명 · 단위테스트 케이스 ID · 통합테스트 케이스 ID · 비고 · 통합시나리오ID · 통합테스트 파일명. 요구사항 묶음마다 행 배경색을 교대(E6E0ED / DBEEF3 / D9D9D9)로 칠해 **같은 요구사항의 세부 행을 묶어** 보여 준다.
- 숨김 "작성가이드": 항목명·설명·예제·필수 표 + 작성 참조사항(추적성 유지, ID는 해당 산출물에 정의되어야 함, 삭제 요구는 삭제 표시·근거 기록).

## 4. 외부 참고

실무 자료들은 정의서에 요구사항 ID·구분·명·상세·출처(요청일)·중요도·난이도·수용여부·검증방법을 두고([위시켓 요즘IT](https://yozm.wishket.com/magazine/detail/924/), [wikidocs 요구사항 문서 작성](https://wikidocs.net/336250)), 추적표(RTM)는 요구사항 ID ↔ 설계(화면) ↔ 테스트 케이스 ↔ 결과를 양방향으로 잇는 표로 설명한다([Apidog RTM](https://apidog.com/kr/blog/yogu-sahang-cujeog-pyo/), [TestRail RTM 가이드](https://www.testrail.com/blog/requirements-traceability-matrix/)). 공식 표준 양식은 확인되지 않았으므로 **발주기관 양식이 있으면 그 양식을 우선**하고(구축 단계 재적재로 수용), 이 시스템의 양식은 위 샘플 관행과 실무 자료를 합친 기본값이다.
